# aIKnownOfYou v0 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. This plan implements the user's approved first-version directory proposal and request to build https://github.com/t-ueda21/aIKnownOfYou.

**Goal:** Ask a short thinking-preference questionnaire once, choose a provisional internal conversation level, and persist concrete personal instructions for Codex and Claude Code.

**Architecture:** A shared JSON catalog, a standard-library Python configuration script, and two setup Skill templates. Setup uses the host AI for selection; normal conversations use native personal instructions with no per-turn program, server, or external LLM API.

**Tech Stack:** Python 3.10+, standard library, JSON, Markdown, unittest.

**Spec:** User requirements and directory proposal in the conversation; binding requirements and interfaces are recorded below. This is an initial implementation, not a validated IQ or personality assessment.

## Global Constraints

- Product name: aIKnownOfYou; setup Skill name: aiknownofyou-setup.
- Ask fixed, qualitative, situation-based choices about thinking. Do not infer settings from prose length, vocabulary, politeness, typos, response time, or personal biography.
- Retain one internal integer L from 80 through 130. The user never has to select it. Store the host AI's provisional selection once; do not automatically retune it during ordinary conversation.
- Preserve accuracy, breadth, speed, organization, important conditions/exceptions/actions, and task/code/review quality at every L. Do not claim an IQ correspondence.
- No MCP, web app, database, daemon, external API key, or third-party Python dependency.
- Keep existing personal instructions outside the managed aIKnownOfYou region byte-for-byte. Reapply without duplicates. Reject malformed/multiple managed regions before writing anything.
- Store personal answers/settings outside the source repository. Use temporary homes for tests. Do not install a profile in the real user or assistant home during development.
- Honor the active Codex global instruction file (nonempty AGENTS.override.md before AGENTS.md), custom CODEX_HOME, and Claude's configuration location.
- Both clients share the catalog and selected profile. Installing the second client can reuse a saved profile. A different catalog version must not silently reinterpret an old profile.
- Commands should produce concise Japanese operational messages and omit the selected L from ordinary output.

## Shared Interfaces

Source files: catalog.json; configure.py; templates/codex/SKILL.md.tmpl; templates/claude-code/SKILL.md.tmpl; README.md; .gitignore; tests/test_configure.py.

Catalog schema:
- schema_version: 1; version: "0.1.0".
- questions: list of {id: "q1".."q8", text, choices: [{id: "A".."D", text, preference_ids: [string]}]}.
- special_choices: [{id: "context"|"none"|"skip", text}].
- selection_rules: {min_answered: 3, fallback_level: 100, evidence_min: 2, instructions: [string]}.
- level_instructions: map from string anchors "80", "90", "100", "110", "120", "130" to Japanese instruction strings.
- preference_rules: map from rule ID to Japanese instruction string.
- common_instructions: list of Japanese instruction strings.

AI apply payload: {catalog_version: "0.1.0", answers: {"q1": ["A"], ... all eight question IDs}, level: integer, evidence: [{question: "q7", choice: "A"}, ...]}.
Each answer has one main choice and optionally a distinct second choice. A special choice appears alone. Below three substantive answers the level must be 100 and evidence may be empty; otherwise evidence includes at least two distinct answered questions and refers only to choices actually selected. Derive preference rule IDs from the catalog, not free-form AI instructions.

CLI contract:
- Global --home PATH sets an isolated user-home base; default is the real user home. An explicit --home ignores host configuration-home environment overrides unless explicit install options are supplied.
- install --target codex|claude-code|both [--codex-home PATH] [--claude-home PATH]. Default target: both. Resolve environment overrides only for the normal-home invocation. Record installed destinations in state so generated commands reuse the same paths.
- questions: print the eight questions and choices without the internal L.
- guide: emit the catalog and apply payload contract for the setup AI.
- apply [--input FILE|-]: validate and persist a new profile, or reapply the saved profile when no input is given; update all installed target instructions.
- status: show installation/configuration/instruction consistency, not the selected L or answers.

Template substitutions: {{COMMAND}} is the correctly shell-quoted command prefix (Python executable, installed configure.py, --home absolute path); {{CATALOG_PATH}} and {{TARGET}} are literal text metadata. On Windows provide a PowerShell command; on POSIX use sh quoting. No shell-built JSON arguments: the setup AI writes a UTF-8 JSON file, calls apply --input with a properly quoted path, and removes only its own temporary file afterward.

Installation layout: ~/.aiknownofyou/runtime/{configure.py,catalog.json,templates/...}; ~/.aiknownofyou/state.json; ~/.aiknownofyou/backups/. Generate target SKILL.md files in the product's personal skill directory. Do not point installed files back to a source checkout.

Instruction markers: <!-- aIKnownOfYou:begin --> and <!-- aIKnownOfYou:end -->. Compile shared quality + selected/interpolated level text + deduplicated preference rules. For in-between integers combine adjacent anchor texts with integer tenth weights; do not include the selected L in the generated instruction or normal output. This is an instruction interpolation, not an experimentally established psychological scale.

## Review Focus

1. Existing instructions with CRLF, BOM, no final newline, malformed or duplicate markers: preserve outside bytes; reject ambiguous regions.
2. Half-completed updates or a failure on the second client: restore files changed by this operation; do not claim all targets applied if a write failed.
3. Custom configuration homes, paths containing spaces/non-ASCII characters, moving the source checkout: installed commands retain valid destinations and references.
4. Unknown IDs, boolean/non-integer levels, missing questions, unsupported versions, fabricated selection evidence: reject before writes.
5. Setup reruns, adding a client, instructions edited after setup: idempotent application and honest status, no silent repeat questionnaire or hidden loss of unrelated text.

## Implementation Decisions

- The GitHub repository was verified empty. A fresh isolated local repository is used; there is no preexisting test baseline.
- Direct git clone is unavailable in this execution environment (proxy connection failure). GitHub plugin tools are used to inspect and synchronize the requested repository; no network policy or credential changes are attempted.
- The user explicitly asked to build the proposed structure. Routine choices and implementation proceed without another design approval round.
- These are repository-owned Skill templates for the user's VS Code tools. They are not an installation into ChatGPT's personal Skill directory.
