# v0.2 実装計画と決定事項

対象: 初回回答から説明可能な規則で L を決め、Codex の日常用 Skill から会話方針を使う。
根拠の整理: [evidence-and-design-rationale.md](../../evidence-and-design-rationale.md)。
これは心理測定として検証した採点法ではなく、初版の再現可能な設定規則である。

## 採用する仕様

- 固定の8場面を維持し、各問を6択に改訂する。各問に80・90・100・110・120・130に対応する選択肢を一つずつ置く。表示位置は設問ごとに変える。
- 単独選択は3点、主副の二選択は2点・1点。一問の合計は常に3点。アンカーごとの分母による補正を行わない。
- 通常回答が3問未満なら `insufficient_answers`。最大点の候補のどれかが異なる2問から支持されなければ `insufficient_support`。どちらも暫定値100を使う。
- 最大候補が一つなら `matched`、隣接する二候補の同点なら中間値を `adjacent_blend`、それ以外の同点なら100を `mixed` として使う。
- 同じ100でも、選ばれた100と暫定値100を記録上で区別する。これらの閾値・重みは製品の暫定規則で、研究から導いた精度ではない。
- 自動選定は11候補。指示の補間は80〜130の全51整数を扱える。数字が大きいほど品質が高くなる設計にはしない。
- 外部入力は `catalog_version` と `answers` のみ。プログラムが `level` と計算過程 `selection` を保存し、再適用時にも再計算して整合を確認する。
- `explain` は明示的に求めたときの読み取り専用監査。通常の完了表示・`status` は数値と回答を表示しない。
- 旧0.1回答は新しい選択肢へ読み替えない。更新時は旧設定と旧指示を保持し、明示的な再設定で新しい8問を受け付ける。
- Codex に `aiknownofyou` 日常用 Skill と `references/profile.md` を作る。AGENTS 管理領域には短い使用指示だけを保存する。初期設定は既存の `aiknownofyou-setup`。
- 全文から日常用 Skill への移行は新しい回答を適用するとき。AGENTS と override の双方に残る管理領域を更新し、領域外の個人設定を保持する。
- サーバー、MCP、データベース、追加モデル API は使わない。既存の Claude 対応を壊さず、今回の日常 Skill 対応は Codex に限定する。

## 実装の分担と順序

1. 現行27テストを隔離ホームで実行し、変更前にすべて成功することを確認する。
2. `selection.py` と選定テストを追加する。代表回答・同点・主副・不足・改ざんの期待値を先に決め、失敗を確認してから実装する。
3. `catalog.json` の質問・対応・6アンカー指示を改訂する。前の正規化案は歴史資料として区別する。
4. `configure.py` に回答のみの入力、保存検証、旧版保持、`explain`、Skill への配置を組み込む。既存の競合検知・バックアップ・復元・引用処理は維持する。
5. setup と日常用 Skill のテンプレートを更新する。利用者に毎回 L や初回質問を要求しない。
6. インストール・再設定・再適用・独立したランタイム・移行・破損検知を隔離ホームで確認する。
7. README と根拠資料を実装済みの状態へ更新し、独立レビューと全テストを行う。
8. ローカル Git に記録し、GitHub の更新前ヘッドを確認して公開する。公開ファイルとローカルの一致を確認する。

## 検証の境界

算術・入力検証・保存と移行・ファイル整合は自動テストできる。質問文を人が意図どおり理解するか、選んだ L で理解や作業結果が改善するか、利用者の VS Code が各応答で Skill を適用するかは別の確認事項である。これらをファイルテストの成功から推測しない。

利用者の PC の `docment/repository/` はこのクラウド環境から操作できていない。隔離ホームでの成功を PC へのインストール成功とは報告しない。
